# AI-документация

Эта директория содержит AI-ориентированную документацию проекта `hexlet-cv`.

Ее цель:
- давать стабильный контекст для AI-ассистентов
- фиксировать правила использования ИИ в проекте
- давать переиспользуемые шаблоны задач
- формировать общее понимание для людей и AI-инструментов

---

## Структура документов

### Основные документы
- `operating-model.md` — правила использования ИИ в проекте
- `project-map.md` — высокоуровневая инженерная карта проекта
- `task-brief-template.md` — шаблон для scoped AI-задач

### Русские mirror-версии
- `operating-model.ru.md`
- `project-map.ru.md`
- `task-brief-template.ru.md`

Русские файлы предназначены для чтения.  
Английские файлы являются source of truth.

---

## Правило канонического языка
Каноническими считаются английские версии.

Это значит:
- для AI-контекста по умолчанию используются английские файлы
- стабильные инструкции для команды по умолчанию ведутся на английском
- русские файлы должны семантически отражать английские
- изменения сначала вносятся в английскую версию, затем синхронизируются в русскую

---

## Правило обновления
При изменении AI-документации:

1. Сначала обновляется английский канонический файл
2. Проверяются формулировки и ограничения
3. Затем синхронизируется русская mirror-версия
4. Смысл, ограничения и invariants должны оставаться согласованными

Русские mirror-версии не обязаны быть дословным переводом, но обязаны сохранять:
- intent
- constraints
- invariants
- sensitive areas
- workflow rules

---

## Как использовать эти документы с ИИ

### Для analysis-задач
Передавать:
- релевантную секцию из `project-map.md`
- релевантную секцию из `operating-model.md`
- локальный контекст задачи

### Для write-задач
Передавать:
- `operating-model.md`
- релевантную часть `project-map.md`
- task brief на основе `task-brief-template.md`

### Для sensitive-задач
Дополнительно передавать:
- явный список allowed files
- явный список forbidden zones
- invariants
- steps проверки результата

---

## Главный принцип
Эти документы нужны, чтобы ИИ оставался полезным, локальным, проверяемым и безопасным.

ИИ должен ускорять инженерную работу, а не вносить неконтролируемые изменения.
